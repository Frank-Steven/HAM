# 0x08 HAM 神谕及系统调用

神谕的定义：一个系统自身之外的影响因素

HAM 需要神谕来完成功能，常见的神谕形式如下：

- 副作用的产生与接收
- 不可预测的递归函数
- 无限循环
- 无限递归
- 随机性

## 神谕的通用接口

集合形式：如一些底层的数据实现方式

单子形式：如一些操作序列的组装方式

### 集合形式神谕

集合形式神谕以“内建函数 + 外来值”的方式存在，调用内建函数只会得到新值，不改变任何已有的值，也不需要传递任何状态。

数组是集合形式神谕的代表：数组无法表示为 Something 标准式，它由 `Array` 这个内建组合创造，一切数组操作（`at`、`map`、`filter` 等）都是 `Array` 组合中的内建函数。内建集合（`Int`、`Num` 等）同样是集合形式神谕。

结构 `()` 也是神谕：它不能参与 `<|` 运算，只能参与 `$`（函数调用）。不定参数包对结构进行的合并运算同样是对结构的神谕运算。

### 单子形式神谕

单子形式神谕以“世界令牌”的方式组织操作序列。系统调用是单子形式神谕的代表。

## 系统调用

HAM 提供一种 monad 形式的系统调用，并提供 monad 转换器神谕将 monad 转换为目标程序。

在编译的时候，需要指定程序的“入口”，这个“入口”是一个表达式，解析为 monad 被 monad 转换器转换后的目标程序。

HAM 可以有多个入口，也可以有多条 monad 链同时存在，甚至允许 monad 链分支，形成树形，但 HAM 的一个入口只对应一个 monad 链，在编译的时候其他部分会被惰性忽略。

你通常需要把 os 在函数之间传递或者覆写来进行系统调用。

### 世界令牌

`os` 是一个不可变的、普通的组合。使用 `os.random` 之类的神谕不会改变 `os`，而是返回一个代表“这次调用之后的世界”的新组合。旧的世界令牌依然有效，因此世界令牌是持久化的。

`os = os.random` 的覆写本质上是手动穿线。把最新的世界令牌沿着计算一路传递下去，形成一条 monad 链。

每次神谕调用的结果存放在新令牌的 `value` 键中，即 `value` 是最近一次神谕调用的结果：

```HAM
os = os.random,        // 请求一个随机值
ans = os.value,        // 读取随机值
os = os.output("hi\n") // 输出副作用
```

### 求值时机

monad 链是数据而不是动作，神谕调用只有在表达式被真正需要时才会生效。`if` 表达式未被选中的分支、从未被提取的组合成员、入口未引用到的声明，都不会触发神谕，而是被惰性忽略。HAM 的求值是按需进行的，monad 链上效果的顺序由数据依赖唯一确定。

由于世界令牌是持久化的，从同一个令牌可以分出多条链，形成树形。从同一令牌分出的链彼此独立；一个入口只取其中一条链进行转换。

### import

外部接口用 `import(name)` 获取，`import` 返回一个组合，可以用提取语法取出需要的键：

```HAM
{ os } = import("os"),   // 操作系统接口
{ cl } = import("cl")    // Common Lisp 后端
```

`os` 提供系统相关的神谕，如 `random`、`input`、`output` 等。调用它们会推进 monad 状态，通常把结果覆写回 `os` 并继续传递。

`cl` 是 monad 转换器神谕的一个实例：`cl(入口表达式)` 把入口的 monad 转换为 Common Lisp 目标程序。编译时以 `--entry` 指定入口，`--output` 指定输出：

```HAM
mainCl = cl(game(os)), // 将 game(os) 编译为 Common Lisp
```

```sh
ham ./guess.ham --entry='mainCl' --output guess
```

### 神谕的能力限制

HAM 不按副作用的种类拆分单子。需要限制某个函数可以使用的神谕时，把世界令牌的子组合传给它即可：

```HAM
play = ({ output, value }) => ... // 只接收输出能力
```

### 并发神谕

并发同样以神谕的形式提供，不引入新的语法。从同一世界令牌分出的链彼此独立，运行时可以并行地求值它们。

`fork` 接受一个 `os -> os` 的函数，让分支拿到分叉点的令牌快照并行执行。`wait` 取回分支的最终令牌。
